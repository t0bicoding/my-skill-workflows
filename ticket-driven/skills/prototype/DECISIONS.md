# Decision Page

Every prototype is handed over with one **decision page**: an HTML page that says in plain words what the prototype settles, asks each decision the user still has to make, with options and your recommendation, and writes all choices into one prompt the user copies back into the chat. The prototype shows; the page asks; the prompt carries the answer back.

It is built once per question, at hand-over ([UI.md › Hand it over](UI.md#7-hand-it-over), [LOGIC.md › Hand it over](LOGIC.md#4-hand-it-over)), and updated whenever the prototype changes.

## What it borrows from /to-html

The page is a /to-html page with one extra section. From [to-html](../to-html/SKILL.md) it takes, unchanged:

- the **house style**: the whole `<style>` block of [page-template.html](../to-html/page-template.html), its section classes, and one accent pair from *to-html › Accent* (UI questions usually *structure*, a measurement or device *a device, a signal*);
- the **picture** rules and forms from [pictures.md](../to-html/pictures.md);
- the **Ground Rules** *Nothing invented*, *Plain language* and *Short*, and the label table for the chat language.

It differs in two ways: it lives in the prototype's question folder, not outside the project, and it is interactive. The decision block (CSS, markup, script) comes from [decision-block.html](decision-block.html): append its CSS to the copied `<style>` block, its markup and script in place of the sections below.

## Where

`<root>/<area>/<question-slug>/decisions.html`, next to the prototype's plan line ([SKILL › Where prototypes live](SKILL.md#where-prototypes-live)). It rides along to the throwaway branch with the question folder, so the prototype's primary source holds what was asked as well as what was built.

If the host can publish an HTML page (an Artifact tool or similar), publish it from there, open it and give the link; otherwise open the file in the default browser and give its path ([SKILL › Deliver it open](SKILL.md#deliver-it-open)). An update goes into the same file and is republished to the same link.

## Sections

In this order. A section with nothing to say is deleted, heading and all; 1, 3, 5, 8 and 9 always stand.

| # | Section | Holds |
|---|---|---|
| 1 | Head | eyebrow `Prototype · <area> / <question-slug>`; a headline that asks the prototype's question in everyday words; a lead of one or two sentences: what you can try and what you decide here; status chip with class `planned`: "Waiting for your decision · n decisions" |
| 2 | Picture | one form from pictures.md. UI: *Options*, one card per variant, its name and what is structurally different about it. Logic: *Flow* of the case that is hard on paper, or *Options* when the model has competing shapes |
| 3 | How to try it | two to four steps: the start command or the file to open; the URL and the `?variant=` keys, or the walkthrough tabs; what to look at |
| 4 | What it clarifies | two or three findings, each a short label and one sentence: what the prototype already shows (a case that breaks, a variant that overflows, the reference comparison). Before the user has looked: what the variants or scenarios disagree about |
| 5 | Decisions | the decision block, below |
| 6 | Deliberately left out | chips: what this prototype does not answer |
| 7 | Still open | a risk or question no decision here settles, and what happens about it |
| 8 | Prompt | the generated prompt, from decision-block.html |
| 9 | Source | the question folder, the ticket that asked, the variant or logic files |

## The decision block

One `.choice` per decision the user has to make. **One to five** decisions, fewer is better: only what the user must settle and what the prototype made visible. What the prototype settles beyond doubt is a finding in section 4, not a decision.

Each decision holds:

- **The question**, as a question the answer to which can be built ("Where does the list of readings sit?", not "Layout?"), and one line on what depends on it and where to see it in the prototype (variant B, walkthrough 2).
- **Two to four options**, each a short name, plus up to two pros and one con in the reader's words. Options are real alternatives the prototype shows or the sources name, never filler. Every decision also gets the **Other** option with a free-text field ("header from B with the list from C").
- **Your recommendation**: the option marked *Recommended* and pre-selected, and one or two sentences why, from evidence: what the prototype showed, the reference comparison, a rule or ADR, the ticket. A reason that rests only on your judgement says so. When the evidence is balanced, say what it hinges on and leave nothing pre-selected (`data-recommended=""`).
- An optional **note** field, for "B, but with the larger font".

## The prompt

Section 8 is generated by the script on every change and holds, in the chat language:

- which prototype (the question folder) and its question;
- one line per decision: the question in short, the chosen option or the free text, whether it follows the recommendation or what the recommendation was, the note;
- a closing line telling you what to do with it: capture the answer and the prototype as the skill says.

A decision without a choice reads "still open". The copy button uses the clipboard; where that is blocked, it selects the text for <kbd>Ctrl</kbd>+<kbd>C</kbd>. Choices are kept in the viewer's browser so a reload loses nothing.

## When the prompt comes back

Take each line as the user's verdict: a free text or a note overrides the option's name; a line still open is asked once, by itself. Then capture the answer and the prototype ([SKILL › Rules](SKILL.md#rules-that-apply-to-both), rule 7): the pasted prompt is the verdict that goes into the ticket or the commit.

If the user wants a new variant or scenario instead, change the prototype and the page together: new option cards, findings and picture, same file, same link.
